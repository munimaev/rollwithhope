# Карта паттернов Obsidian → компонент

Живой журнал разбора статей хранилища для skill `sync-content`. Пополняется по мере
прохода по корпусу `01︱📚︱Правила/**/*.md` в порядке книги. Формат: паттерн исходной
заметки → как отображается на сайте (компонент или «обычный `.prose`»).

Базовый контракт разметки уже описан в `templates/guidelines/40-markup-contract.md`
(маркеры заголовков, `option-list` с 🔸, callout'ы, `wikilink`/`wikilink--dead`,
таблица-галерея карт, `<br>` в ячейках, авто-nav вместо ручных prev/next-строк) — здесь
фиксируются только решения, принятые в живую поверх/в дополнение к этому контракту.

## Пройдено

- **`00︱Introduction/What Is This.md`**, **`The Basics.md`** — без отдельных
  компонентов. Абзацы вида `**Термин:** описание` (без 🔸, не `option-list`) →
  обычный `.prose`-абзац. Финальный блок `---` + курсивная строка «Источник: ...» →
  обычный `<hr>` + `<p>`, без отдельного компонента атрибуции.
- **`01︱📗︱Подготовка к приключениям/01︱📗︱Описание мира/*`** — вся папка
  `visibility: private`, на сайт не попадает целиком.
- **`02︱📗︱Создание персонажа/00︱Создание персонажа.md`** — без новых паттернов.
  Полностью курсивный лид-абзац, безразмерная иллюстрация не первой строкой,
  `[!tip]` без заголовка — всё укладывается в существующие компоненты.
- **`02︱📗︱Создание персонажа/01︱Шаг 1. Класс и подкласс.md`** — повторяющиеся
  `[!dh-step]` с картинкой+вики-ссылкой внутри (карточки выбора подкласса) →
  **обычный `Callout[data-type=step]`**, без отдельной вёрстки-карточки.
- **`02︱📗︱Создание персонажа/01︱Шаг 2. Выберите наследие.md`** — блок
  `​```dataviewjs` с `dv.pages("#тег")` → 3-колоночная таблица ссылок на публичные
  заметки с этим тегом. **Компонент: `dataviewjs-block`.** Обобщить логику `sync` с
  единственного захардкоженного `#ancestry` (см. `Архитектура.md`) на произвольный тег —
  сейчас любой другой dataview останавливает сборку, это нужно снять для данного паттерна.

## Компоненты (сводная таблица)

| Компонент | Паттерн в заметке | Примечание |
|---|---|---|
| `dataviewjs-block` | ```` ```dataviewjs ... dv.pages("#тег")...dv.table(...) ```` | Обобщённый: любой тег, не только `#ancestry`. 3 колонки ссылок. |
| _(без компонента)_ | `**Термин:** текст` абзацем, без 🔸 | Обычный `.prose` |
| _(без компонента)_ | `---` + курсив «Источник: ...» в конце статьи | Обычный `<hr>` + `<p>` |
| _(без компонента)_ | `[!dh-step]` с картинкой и вики-ссылкой внутри | Обычный `Callout[data-type=step]` |

- **`01︱Шаг 3` — `01︱Шаг 7`** — без новых компонентов:
  - обычная цитата `>` без `[!тип]` под заголовком (Шаг 3) → простой `<blockquote>`
    (уже в контракте);
  - `[[#Заголовок|текст]]` — вики-ссылка на заголовок **внутри той же статьи** (Шаг 7) →
    обычный `Link`/`wikilink`, резолвится в `#slug` текущей страницы (не отдельный
    компонент, но новое правило резолва для `sync`/`wikisyntax.ts`);
  - `**Категория:** *длинный список примеров через запятую курсивом*`, повторяется
    подряд 5 раз (блок «Примеры опыта», Шаг 7) → обычный `.prose`-абзац.

- **`01︱Шаг 8`, `01︱Шаг 9`** — без новых паттернов.
- **`03︱📗︱Классы/01︱Классы.md`** — заголовки `######` (h6) с эмодзи-маркером 🟨 →
  маркер (`data-marker="minor"`) применяется единообразно на любом уровне заголовка
  h2–h6, не только h2–h4 как буквально написано в контракте.

- **`03︱📗︱Классы/02︱Бард/Бард.md`** (страница класса):
  - блок из фиксированного набора `[!dh-step]` сразу после иллюстрации (Домены,
    Стартовое уклонение, Стартовый максимум ран, Предметы класса, Подклассы) →
    **компонент `class-basis`** (сводка класса), не обычный `Callout`.
  - `🟨 **Текст**` отдельной строкой без `#` (название хода/способности перед
    описанием, напр. свойство Надежды) → **поднимается в настоящий заголовок**
    (h5/h6 с маркером), не остаётся жирным текстом в абзаце.
- **`03︱📗︱Классы/02︱Бард/Бард — Трубадур.md`** (страница подкласса):
  - таблица `cssclasses: white-table`, используемая чисто как сетка-раскладка
    картинок карт подкласса (без текстовых псевдо-заголовков уровня, в отличие
    от галереи по тирам) → **компонент `class-card-gallery`**, отдельно от
    обычной table→card-gallery с заголовками уровней из контракта.
  - структура «Свойства подкласса — Основа/Специализация/Мастерство» (h4 + h6 +
    абзац) — без нового компонента, обычные заголовки с маркером.

- **`Бард — Мастер слова.md`, `Воин.md`, `Волшебник.md`, `Друид.md`** — та же
  структура класса/подкласса, без новых паттернов.
- **`02︱Друид/Звериные формы.md`** — ряд вики-ссылок через « • » как ручная
  горизонтальная навигация по связанным страницам (тирам), в теле статьи, не в
  футере prev/next → **не выводится на сайте вообще** (дропается при sync, как и
  ручные строки «⬅️/➡️ Предыдущая/Следующая страница»).
