# rollwithhope

Правила Daggerheart на русском. Vue 3 + Vite + `vite-ssg`, контент приходит из личного
Obsidian-хранилища и коммитится в этот репозиторий как обычные файлы.

## Три места и границы между ними

1. **Хранилище Obsidian** (`.../iCloud~md~obsidian/Documents/DaggerHeart`) — источник контента,
   отдельный от этого репозитория, приватный, никогда не публикуется целиком. Путь передаётся
   через `VAULT_PATH`. Внутри — папка `01︱📚︱Правила` (сами статьи) и `96︱🛠️︱Сайт`
   (то немногое из хранилища, что редактируется руками: `Разделы.yml`, `Слаги.yml`,
   `Архитектура.md`, `Design System/`) — её `sync` тоже читает.
2. **Этот репозиторий** — код сайта (`src/`) и **вычисленные** артефакты (`content/`).
   `content/pages/**/*.vue`, `content/images/**`, `content/manifest.json` — генерируются
   скриптом `scripts/sync` с нуля при каждом запуске. **Никогда не редактируются руками** —
   любая ручная правка будет затёрта следующим прогоном `sync`.
3. **`templates/`** — локальный (в `.gitignore`, не коммитится) снимок дизайн-системы,
   экспортированный из артефакта Claude Design. Чистая разметка/CSS-демо (`preview.html` +
   `README.md` на каждый из ~32 компонентов), не настоящие Vue-компоненты — справочник при
   реализации `src/components/*.vue`, а не код для копирования как есть.

## Правило публикации (обязательно к соблюдению)

- На сайт попадают **только** заметки с `visibility: public` во frontmatter. Заметки без
  этого поля (в том числе без frontmatter вовсе) — приватные по умолчанию, не публикуются.
- Картинки и другие файлы попадают в `content/images/` **только** если на них ссылается (или
  их вставляет) публичная заметка. Ничего "на всякий случай".
- Это не подлежит смягчению даже для удобства разработки/отладки — если что-то не помечено
  `public`, оно не должно оказаться ни в `content/`, ни в git-истории публичного репозитория.

## Правило воспроизводимости правок (обязательно к соблюдению)

- Любая правка отображения статьи (вёрстка, стиль, поведение компонента, обработка
  markdown-паттерна) должна пережить следующий `sync` и примениться **ко всем
  релевантным случаям** в корпусе — не только к одной статье, на которой её заметили.
- Правка живёт в одном из системных мест: скрипте `scripts/sync/**` (если дело в
  генерации разметки/данных), компоненте `src/components/**` или `src/pages/**` (если
  дело в рендере уже сгенерированного контента), либо третьим способом того же уровня —
  но не как ручная правка внутри `content/pages/**/*.vue`. Эти файлы вычисляются заново
  каждым прогоном `sync`, поэтому точечный хак в одном из них молча исчезнет при
  следующей синхронизации и не решит проблему для остальных статей с тем же паттерном.
- После правки — обязательно прогнать `sync` заново (а не просто проверить один файл
  глазами) и убедиться, что исправление действительно разошлось по всем местам, где
  встречается паттерн, прежде чем считать задачу выполненной.
- Если правка дизайна меняет то, что описано в `templates/` (разметка/CSS компонента,
  задокументированные в его `preview.html`/`README.md`) или в дизайн-системе хранилища
  (`96︱🛠️︱Сайт/Design System/` внутри vault) — недостаточно поправить только
  `src/components/**`/`src/styles/**`. Оба источника — `templates/` (локально, руками,
  хоть он и в `.gitignore`) и `Design System/` в хранилище (руками, не через `sync`) —
  нужно привести в соответствие синхронно с кодом, иначе они разойдутся и следующая
  правка по ним будет ориентироваться на устаревший снимок.

## Текущее состояние фронтенда

Коммит `chore: reset frontend content` (2026-09-23) намеренно снёс старый фронтенд
(`src/pages`, большинство `src/components`, старые `content/pages/**/*.html`, `src/styles`) —
пересобираем заново по дизайн-системе из `templates/`. `content/manifest.json` при этом уцелел
(234 страницы) — валиден как справочник структуры/URL/тегов, но сами тела статей
(`content/pages/`) сейчас не существуют и будут пересозданы `sync`.

**Решение по формату (2026-09-23):** генерируемые страницы — `content/pages/**/*.vue`
(настоящие SFC-компоненты), не `.html`. Тот же принцип, что был у `.html`-варианта
(вычисляется, не редактируется руками), просто другое расширение — `sync` должен быть
переписан под эмиссию `.vue`, разметка внутри следует контракту `templates/guidelines/40-markup-contract.md`.

## Пайплайн sync

`scripts/sync/index.ts` (Node/TS, без состояния — каждый запуск обходит весь
`01︱📚︱Правила` заново и полностью пересобирает `content/`):

```bash
VAULT_PATH=/путь/к/хранилищу npm run sync          # предупреждения не блокируют
VAULT_PATH=/путь/к/хранилищу npm run sync:strict   # любое предупреждение — стоп
```

Подробности пайплайна (frontmatter → метаданные, слаги через `Слаги.yml`, вики-ссылки,
картинки, callout'ы, dataview-таблица наследий, запрещённый HTML) — в
`96︱🛠️︱Сайт/Архитектура.md` внутри хранилища; не дублировать здесь, сверяться с оригиналом.

## Git/публикация — важно

- `npm run sync` — чисто локальная пересборка `content/`, ничего никуда не пушит. Можно
  выполнять свободно, когда нужно посмотреть diff.
- Перед `git push` в публичный репозиторий — обязательно: отчёт `sync` (добавлено/изменено/
  пропало/предупреждения) + явное подтверждение пользователя + проверка, что в `content/`
  не осталось заметок без `visibility: public`. Не пушить самостоятельно без этого шага.
- Node 22, npm (не pnpm).

## Статус: первая полная прогонка (2026-09-23/24)

По прямому указанию — приоритет был «залить всё, что есть, в онлайн», а не точность
компонентов. Сделано:

- `sync` переписан на эмиссию `content/pages/**/*.vue` (реальные SFC), полностью
  переписан пайплайн разметки под контракт `templates/guidelines/40-markup-contract.md`:
  заголовки получили id/маркеры/якоря (`scripts/sync/markdown/headings.ts` — этого не
  было в коде вообще, только в документации), callout'ы → `.callout[data-type]`,
  вики-ссылки → `.wikilink`/`.wikilink--dead`, внутристатейные `[[#Заголовок]]` — резолвятся
  в `#slug`, картинки-карты → `figure><img data-lightbox>`, ручные prev/next-строки и
  ряды `[[…]] • [[…]]` — дропаются (заменяются генерируемой навигацией).
- Картинки перенесены в `public/images/` (не `content/images/`) — Vite не умеет отдавать
  как статику относительные/даже some абсолютные `src` внутри настоящих `.vue`-шаблонов
  без `transformAssetUrls: false` в `vite.config.ts`; URL запекаются в `sync` с префиксом
  `SITE_BASE` (по умолчанию `/rollwithhope/`), т.к. `<img src>` в сгенерированном
  `.vue` — статическая строка, `import.meta.env.BASE_URL` в ней недоступен.
  Аналогично — 3 иконки `public/icons/hands-{none,one,two}.svg` под сырые `<img>` из
  таблицы параметров оружия (единственный такой случай в корпусе).
  **Важно:** при смене `SITE_BASE` нужен повторный `sync` — не только `build`.
- Фронтенд собран заново на CSS дизайн-системы (`templates/css/*` скопированы в
  `src/styles/`, шрифты — `@fontsource-variable/{alegreya,literata}`, не Google Fonts):
  `App.vue`, `HomeTopBar`, `SidebarMenu`+`SidebarTreeNode`, `CardLightbox`,
  `ArticlePage`/`HomePage`/`NotFoundPage`, TOC — через `useToc.ts` (реактивный мост
  между `ArticlePage` и `App.vue`, т.к. колонка «На этой странице» — часть шапки
  приложения, а не самой статьи).
- `npm run sync` (233 страницы) → `npm run build` → `npm test` — всё проходит чисто.

### Известный бэклог (сознательно не делали ради скорости)

- ~~Дерево сайдбара плоское~~ — **исправлено (2026-09-24).** Папки хранилища без
  публичной `Index.md` теперь получают синтетический группирующий узел (`isVirtual:
  true`, `url: null`, без `.vue`-файла) в `scripts/sync/page-tree.ts`; дети reparent-ятся
